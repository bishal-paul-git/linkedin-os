# Memory Policy

## Write facts, not guesses

Profile details, relationship state, actions, dates, and outcomes should be factual.

When interpretation is useful but uncertain, prefix it with `Inference:`.

## Minimum useful memory

For an active relationship retain:

- exact LinkedIn URL;
- name, current role, company;
- relationship type and owner;
- connection status;
- why the relationship matters;
- last meaningful interaction;
- open ask/question/commitment;
- next action and date;
- opportunity signal/stage where supported;
- approval/execution references.

## Do not duplicate

Before creating a contact, use LinkedIn URL first and name+company second.

Before creating an approval action, search for the same contact/action and idempotency key.

## Do not over-store

Prefer concise summaries to full message transcripts unless exact wording is needed for a commitment, approval, or dispute.

## Memory update triggers

Update memory when:

- a new relevant person is discovered;
- qualification changes;
- a connection is actually sent/accepted;
- a meaningful message is received/sent;
- a commitment is made/completed;
- an opportunity changes stage;
- a public engagement action occurs;
- approval/execution state changes;
- a security blocker occurs.
